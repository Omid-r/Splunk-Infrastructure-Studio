# محیط آزمایشگاهی (Laboratory)

این پوشه یک نمونهٔ **کاملاً جدا** از Splunk Infrastructure Studio را اجرا می‌کند: دیتابیس، کانف‌های نودها،
spool رویدادها و لاگ‌های آزمایش همگی داخل `lab/.lab-data/` نوشته می‌شوند و هرگز به `./data` (محیط توسعه)
دست نمی‌زنند.

## اجرا

```bash
node lab/start-lab.mjs              # http://127.0.0.1:8553  (حالت dev)
node lab/start-lab.mjs --port=8600  # پورت دیگر
node lab/start-lab.mjs --prod       # بعد از `npm run build`
node lab/start-lab.mjs --reset      # حذف کامل داده‌های آزمایشگاه و شروع از صفر
```

اگر `npm` در `PATH` شما کار نمی‌کند، همان فایل را با نود مستقیم اجرا کنید:

```bash
"<مسیر node.exe>" lab/start-lab.mjs
```

اولین اجرا:
1. `lab/.lab-data/` ساخته می‌شود.
2. دو راز تصادفی (`SESSION_SECRET`, `SECRET_ENCRYPTION_KEY`) در `lab/.lab-data/lab-secrets.json` با مجوز ۶۰۰
   ذخیره می‌شوند — هرگز در لاگ یا UI نمایش داده نمی‌شوند.
3. مرورگر را روی `http://127.0.0.1:8553` باز کنید و **راه‌اندازی اولیه** را کامل کنید
   (نام کاربری، رمز ≥ ۱۰ کاراکتر، نام Workspace و **allowlist** شبکه).

## مسیر نتیجه گرفتن: صفحهٔ «محیط آزمایشگاهی»

`/lab-env` هشت قدم را به‌ترتیب اجرا می‌کند و برای هر قدم **شاهد واقعی** نشان می‌دهد:

| قدم | کاری که واقعاً انجام می‌شود | نتیجهٔ قابل‌مشاهده |
|---|---|---|
| موجودی نمایشی | `scan_jobs` + `scan_snapshots` با دیتاست DEMO | تعداد هاست/پورت، برچسب DEMO |
| طراحی معماری | فرمول‌های sizing → `architecture_designs` | نودها، منابع، فرضیه‌ها |
| استقرار Local Lab | preflight → نوشتن `manifest.json` و فایل‌های onboarding | وضعیت job و اعتبارسنجی‌ها |
| ساخت نودها | ساخت دایرکتوری conf و رکورد `lab_nodes` | مسیر کانف هر نود |
| روشن کردن نودها | `net.createServer` واقعی روی `127.0.0.1` | پورت ingest/mgmt هر نود |
| تزریق لاگ نمونه | خط‌های واقعی فایل‌های `lab/sample-data` عبر TCP | افزایش خطوط `events.jsonl` + نتیجهٔ جستجو |
| بستهٔ شواهد | tar.gz (ustar + gzip) با manifest | حجم، sha256، فایل‌ها، موارد skip |
| خاموش کردن نودها | بستن listenerها | پورت‌ها آزاد؛ داده‌ها باقی می‌ماند |

«اجرای همهٔ مراحل» قدم‌ها را به‌ترتیب اجرا می‌کند و در اولین شکست می‌ایستد — نتیجهٔ ساختگی نمایش داده نمی‌شود.

## داده‌های نمونه

`lab/sample-data/*.log` **دست‌ساز** و با برچسب `DEMO DATA` در سطر اول هر فایل هستند:
- هیچ میزبان، کاربر، اعتبارنامه یا IP واقعی در آنها نیست (بازه‌های ۱۹۸.۵۱.۱۰۰.۰/۲۴ و ۲۰۳.۰.۱۱۳.۰/۲۴ طبق RFC 5737 رزرو اسناد هستند).
- برنامه این فایل‌ها را از دیسک می‌خواند و از مسیر واقعی TCP → forwarder → indexer → spool می‌فرستد؛
  اگر تحویل ناقص باشد، همان‌قدر صادقانه گزارش می‌شود.

## محدودیت‌های امنیتی (همان‌ها در آزمایشگاه هم جاری است)

- هیچ اسکن شبکه‌ای خارج از allowlist تعریف‌شده انجام نمی‌شود؛ `0.0.0.0/0` رد می‌شود.
- نودهای آزمایشگاهی فقط روی `127.0.0.1` گوش می‌دهند.
- بدون brute force، حدس credential، exploit، stealth scan، persistence یا دور زدن احراز هویت.
- عملیات توقف نودها در UI با تأیید جدا انجام و در حسابرسی ثبت می‌شود.
- این نودها Splunk Enterprise واقعی نیستند؛ فقط شبیه‌ساز رفتار جمع‌آوری/فوروارد برای آزمایش سناریو.

## پاک‌کردن

```bash
node lab/start-lab.mjs --reset
```

یا حذف `lab/.lab-data/`. لاگ‌های `lab/sample-data` بخشی از مخزن هستند و حذف نمی‌شوند.
